# 공정관리 분석기 (XER 기반)

Primavera P6에서 내보낸 **XER 파일을 업로드하면 공정표를 다시 계산(CPM)하고 분석**하는 팀 공유 웹앱입니다.
업로드한 결과는 서버에 저장되어 팀원 모두가 같은 화면을 봅니다.

## 주요 기능

| 화면 | 내용 |
|---|---|
| 목록 | 팀이 올린 XER 목록(업로더·메모·Data Date), 원본 XER 다운로드, 삭제 |
| 개요 | 예상 준공일, 목표 준공일, 잔여 작업일, 공정률, 상태별 개수, 주공정 수, DCMA 통과 수, 마일스톤 |
| 공정표 | WBS별 간트차트(일/주/월/분기 배율), 주공정 빨간색, 계획(Target) 막대, Total Float 꼬리, Data Date 선, 검색·필터, 클릭하면 선·후행 관계와 관계선 표시 |
| 주공정 | 최장 경로(Longest Path) 역추적, 준주공정(TF ≤ N일) |
| DCMA 14 점검 | Logic, Leads, Lags, 관계 유형, Hard Constraints, High Float, Negative Float, High Duration, Invalid Dates, Resources, Missed Tasks, CP Test, CPLI, BEI |
| S-Curve | 계획(Target), Early, Late 누적 곡선과 실적 공정률 |
| P6 일정 비교 | XER에 저장된 P6 계산값과 엔진 재계산값의 차이(검증용) |
| 업데이트 비교 | 두 업로드(예: 3월과 4월)의 준공일 변동, 추가·삭제·변경 액티비티 |
| 내보내기 | 액티비티 목록 CSV(엑셀 호환, UTF-8 BOM) |

## AI·의사결정 기능

계산은 CPM 엔진이 맡고, AI는 엔진 결과를 **도구로 조회해 해석·정리**합니다. 날짜와 일수는 항상 엔진 계산값이고, 원본 공정표를 바꾸는 작업은 사용자가 승인한 것만 반영합니다.
AI 키가 없으면 ①을 제외한 모든 기능이 규칙·통계 기반으로 동작합니다.

| # | 화면 | 기능 | AI 없이 |
|---|---|---|---|
| ① | AI 어시스턴트 | 자연어 질의. AI가 검색, 주공정, DCMA, 지연분석, What-if, 리스크 도구를 호출해 답하고, 답변의 작업을 공정표에서 강조 | 사용 불가 |
| ② | 월간 보고서 | 지연 원인, 주공정, 향후 1개월, 리스크로 보고서 초안 작성. 화면에서 수정 후 Word(.docx) 다운로드 | 템플릿 문장 |
| ③ | DCMA 14 점검 | 항목별 조치 가이드와 AI 우선순위 조치안 | 규칙 가이드 |
| ④ | 지연 원인 | 이전 업데이트 대비 최장 경로를 따라 작업별 **새로 발생한 지연**(기여도) 산정 | 동일 |
| ⑤ | What-if | 공기, 관계, Lag, 진도를 바꿔 재계산. 시나리오 저장과 **수정 XER 다운로드**(P6로 가져오기) | 동일 |
| ⑥ | 관계 추천 | Open End 작업의 누락 관계 추천, What-if 검증 후 XER 반영 | 규칙 추천 |
| ⑦ | 공종 분류 | 표준 공종 분류와 명칭 표준화 | 키워드 규칙 |
| ⑧ | 리스크 | 몬테카를로 P50/P80/P90 준공일, 목표 달성 확률, 주공정 지수 | 동일 |
| ⑨ | 리스크 | 지연 위험 점수(여유, 최장경로, 계획 대비, 진도 부진, 공종 실적, 업데이트 간 순연 추세) | 동일 |
| ⑩ | 벤치마크 | 팀 전체 프로젝트의 공종별 실적/계획 공기 비율, 과소 계획 의심 작업 | 동일 |
| ⑪ | 작업일보 진도 | 작업일보 문장에서 착수·완료·공정률을 추출해 진도 입력안 생성, 확인 후 XER 반영 | 정규식 추출 |

### 사용자·권한 (읽기는 모든 프로젝트, 쓰기는 자기 프로젝트만)
- 계정이 없으면 공개 모드(또는 `APP_TOKEN`)로 동작합니다. 관리자를 만들면 로그인이 필수가 됩니다.
```bash
python -m app.auth create-admin admin
```

| 전역 역할 | 읽기 | 쓰기 |
|---|---|---|
| `viewer`(조회) | 모든 프로젝트 | 불가 (What-if·만회안 계산, 수정 XER·엑셀 리포트 다운로드는 가능) |
| `editor`(편집) | 모든 프로젝트 | 새 프로젝트 생성, **자기 프로젝트**(소유자·멤버)만 편집 |
| `admin`(관리자) | 모든 프로젝트 | 모든 프로젝트, 사용자·팀 설정 관리 |

- **소유자:** 새 프로젝트를 처음 올린 사람이 소유자가 됩니다.
  - 소유자는 프로젝트 설정 화면이나 '👥 프로젝트 권한' 화면에서 멤버를 추가·제외하고 업로드를 삭제할 수 있습니다.
  - 마지막 소유자는 제외할 수 없습니다.
- **멤버:** 업데이트 업로드와 리스크·제약·약속·시나리오·베이스라인·설정·사진 등 프로젝트 데이터를 편집할 수 있습니다.
- **계정 도입 전에 올린 프로젝트:** 최초 업로더와 같은 이름의 계정이 있으면 자동으로 소유자가 됩니다. 그런 계정이 없으면 관리자가 소유자를 지정할 때까지 관리자만 편집합니다.
- **교육용 샘플 프로젝트:** 편집 권한자 누구나 실습할 수 있습니다.
- **권한 검사 위치:** 서버가 모든 변경 요청을 프로젝트 기준으로 검사합니다. 화면에서는 읽기 전용 프로젝트에 '👁 읽기 전용'을 표시하고 편집 버튼을 숨깁니다. 거부된 요청은 감사 로그에 남습니다.
- **내 정보:** 상단 '👤 내 정보'에서 내 권한과 편집 가능한 프로젝트를 보고, 비밀번호를 바꿉니다(현재 비밀번호 확인, 변경 후 다시 로그인).
- **보안:**
  - 비밀번호는 scrypt로 해시하고, 세션은 HttpOnly·SameSite=Strict 쿠키로 관리합니다.
  - 변경 요청은 CSRF 헤더를 검사하고, 로그인 5회 실패 시 10분 잠급니다.
  - XML은 `defusedxml`로 파싱합니다.
- **HTTPS:** HTTPS 리버스 프록시 뒤에서 운영할 때는 `SECURE_COOKIE=1`로 설정합니다.

### AI 설정 (서버의 Claude CLI 사용, API 키 불필요)

AI 기능은 서버에 설치·로그인된 **Claude CLI**(`claude -p`)를 호출합니다. 별도 API 키를 앱에 넣지 않습니다.

```bash
claude --version
```
위 명령이 동작하고 앱을 실행하는 계정으로 로그인되어 있으면 AI가 켜집니다.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `AI_PROVIDER` | `cli` | `off`면 AI 끔(규칙 기반으로만 동작) |
| `CLAUDE_BIN` | PATH의 `claude` | CLI 실행 파일 경로 |
| `AI_MODEL` / `AI_MODEL_BULK` | CLI 기본값 | 대화·보고서용 / 대량 분류·추출용 모델 |
| `AI_TIMEOUT` | `300` | 호출당 제한 시간(초) |
| `AI_MAX_CONCURRENCY` | `2` | 동시에 실행할 CLI 수 |
| `AI_MAX_BUDGET_USD` | (없음) | 호출당 최대 비용 |

**보안 설계**
- `--tools ""`로 CLI의 기본 도구(명령 실행, 파일 읽기·쓰기)를 모두 끕니다.
- `--strict-mcp-config`로 앱이 제공하는 **읽기 전용 공정 조회 도구**(`app/mcp_server.py`, MCP stdio)만 허용합니다. What-if도 사본으로 계산만 합니다.
- `--setting-sources ""`로 서버의 사용자 설정과 훅을 불러오지 않습니다. 빈 임시 폴더에서 실행하고 세션 기록을 남기지 않습니다.
- 공정 데이터(액티비티명, 날짜 등)는 CLI를 통해 Claude로 전송됩니다. 계약상 외부 전송이 제한되면 `AI_PROVIDER=off`로 두세요.
- 호출 기록(기능, 사용자, 토큰)은 관리 화면의 'AI 사용량'에서 봅니다.

## 사용성(UI/UX)

- **공통:** 모든 표의 Activity ID를 누르면 상세 패널(선후행, 리스크, 제약, 변경 이력)이 열립니다. 표마다 엑셀 내보내기, 머리글 용어 도움말(?)을 제공합니다.
- **AI 패널:** 어느 화면에서든 `Alt`+`A`로 열고, 보고 있는 화면 맥락을 함께 보냅니다.
- **홈:** '오늘 확인할 것'(기한 지난 제약, 음수 여유, 준공 지연, 건전성 하락 등)과 ★ 관심 프로젝트를 보여 줍니다.
- **프로젝트 헤더:** 업데이트 전환, 최신 여부, 계산 방식을 표시합니다.
- **메뉴:** 4개 그룹, 18개 화면입니다. 업데이트 분석, 건전성·DCMA, 리스크·예측은 하나로 통합했습니다.
- **공정표:** 드래그 이동, Ctrl+휠 확대, 열 선택과 너비 조절, 베이스라인 겹쳐 보기, 최장경로 관계선, 팀 공유 보기 저장, 키보드 탐색을 지원합니다.
- **현장 모드(📱):** 큰 체크 버튼, 사진 첨부(JPG/PNG/WEBP, 3MB, 형식 검사), 오프라인 임시 저장 후 자동 전송.
- **권한별 화면:** 조회 권한에는 편집 버튼을 숨깁니다. 오래 걸리는 작업은 진행률과 취소를 보여 주고, 확인·입력은 앱 대화상자로 처리합니다.
- **테마·접근성:** 어두운 테마, 키보드 단축키(`?`), 포커스 표시, 본문 바로가기, 색 외에 기호(✓ ✕ ▲ ▼)를 함께 씁니다.

## MS Project 가져오기

| 형식 | 처리 |
|---|---|
| MS Project XML(.xml, MSPDI) | 직접 해석 |
| MS Project 파일(.mpp), 템플릿(.mpt), MPX(.mpx), Primavera P6 XML | [MPXJ](https://www.mpxj.org)(LGPL)로 MSPDI로 변환한 뒤 해석. Java와 `mpxj`·`JPype1` 패키지 필요. 별도 프로세스에서 120초 제한으로 실행 |

- **가져오는 항목:**
  - WBS(요약 작업 계층, OutlineNumber 기준)
  - 캘린더(근무 요일·시간, 예외일, 기준 캘린더 상속)
  - 기준 계획(Baseline0 → 계획 날짜)
  - 진도(실적일, 공정률, 잔여 기간)
  - 제약조건(ASAP 이외 7종), Deadline(→ 보조 제약)
  - 관계 4종과 Lag(일·%·경과 시간)
  - 자원·비용(→ EVM)
- **제외:** 비활성 작업과 외부·하위 프로젝트 작업은 빼고 결과에 알려 줍니다.
- **가져오기 결과 창:** 업로드 후 작업·관계·WBS·캘린더·비용 건수와 확인할 점이 나옵니다. 확인할 점의 예: 베이스라인 없음, % Lag 환산, 경과 Lag 근사, 상태 날짜 없음.
- **한계:** 작업 분할(split), 리소스 평준화 지연(leveling delay), 사용자 정의 필드, 여러 베이스라인(1~10)은 가져오지 않습니다.

## 📊 엑셀 리포트 (회사 양식 그대로 출력)

1. 회사 보고 양식(.xlsx)에 자리표시자를 넣어 올립니다. 업로드할 때 인식한 필드와 알 수 없는 필드(오타)를 알려 줍니다.
2. 프로젝트와 업데이트를 선택합니다.
3. '엑셀 리포트 만들기'를 누르면 양식대로 채운 엑셀을 내려받습니다.

| 문법 | 예 | 결과 |
|---|---|---|
| 값 | `{{project.finish}}` | 셀 서식이 날짜면 날짜 값, 숫자면 숫자 값 |
| 문장 속 값 | `{{project.name}} ({{report.month}})` | 문자열 |
| 표(행 반복) | 한 행에 `{{critical.code}}` `{{critical.name}}` … | 항목 수만큼 아래로 채움 |
| 개수 제한·순번 | `{{late[20].code}}`, `{{critical.#}}` | 20건까지 / 1,2,3… |
| 서식 | `\|date:%Y.%m.%d` `\|num:1` `\|pct` `\|default:-` | |

- **필요한 것만 계산:** 리스크 시뮬레이션이나 AI 요약 같은 무거운 값은 양식에 그 필드가 있을 때만 계산합니다.

- **따라하기:** 교육용 샘플 프로젝트(2회 업데이트, 베이스라인, 리스크)를 자동으로 준비한 뒤, 실제 화면 요소를 강조하며 단계별로 안내합니다. 직접 클릭·입력하면 다음 단계로 넘어갑니다.
- **화면별 도움말:** 각 화면의 '? 사용법' 버튼으로 해당 화면 설명, 따라하기, 관련 강의, 용어를 엽니다.
- **처음 방문:** 처음 프로젝트를 열면 2분 둘러보기를 제안합니다.
- **진도:** 계정별로 서버에 저장되고, 공개 모드에서는 브라우저별로 저장됩니다. 관리자는 팀 학습 현황을 봅니다.
- **용어 사전:** 검색할 수 있습니다.

### CPM 엔진 지원 범위
- FS / SS / FF / SF 관계, 양수·음수 Lag(선행 액티비티 캘린더 기준)
- 액티비티별 캘린더: 작업 요일과 예외일(공휴일) 반영, 일 단위 계산
- 진도 반영: 완료는 실적일 고정, 진행중은 Data Date부터 잔여공기, 미착수는 Data Date 이후로만 일정 배치. 순서 역전 진도는 Retained Logic으로 처리
- 제약조건: Start/Finish On, On or After, On or Before, Mandatory Start/Finish
- 프로젝트 Must Finish By 날짜 기준 Total Float(음수 여유 포함), Free Float
- 순환 관계(Loop) 탐지와 경고

### 알려진 한계
- 계산 단위가 **일**입니다. 시간 단위로 계산하는 P6와 반나절 차이가 날 수 있습니다.
- Retained Logic만 지원합니다(Progress Override는 미지원). LOE와 WBS Summary는 일반 작업처럼 계산합니다.
- 자원 평준화와 비용(EVM)은 아직 없습니다.

## 실행 방법

### 로컬 PC 설치 (Windows / macOS)
1. **Python 3.10 이상** 설치: https://www.python.org/downloads/ (Windows는 설치 첫 화면에서 **Add python.exe to PATH** 체크)
2. 이 저장소를 내려받아 압축을 풉니다(GitHub → Code → Download ZIP, 또는 `git clone`).
3. 설치(처음 한 번): Windows는 `install_windows.bat` 더블클릭, macOS·Linux는 터미널에서 `./install_mac_linux.sh`
4. 실행: Windows는 `start_windows.bat`, macOS·Linux는 `./start_mac_linux.sh` → 브라우저가 http://localhost:8000 으로 열립니다. 실행 창을 닫으면 종료됩니다.

- 데이터는 `data/app.db` 한 파일에 저장됩니다. 백업은 이 파일을 복사하면 됩니다.
- 관리자 계정을 만들지 않으면 계정 없이(모두 편집 가능) 사용합니다. 나중에 `.venv\Scripts\python -m app.auth create-admin 아이디`로 만들 수 있습니다.
- **AI 기능**: PC에 Claude Code CLI(`claude`)가 설치·로그인되어 있으면 자동으로 켜지고, 없으면 꺼진 상태(규칙 기반)로 실행됩니다.
- **.mpp 파일**: MS Project .mpp를 올리려면 Java 21(예: Eclipse Temurin)이 필요합니다. XER·MS Project XML은 Java 없이 됩니다.
- **동료 접속**: `start_windows.bat`의 `127.0.0.1`을 `0.0.0.0`으로 바꾸고 방화벽에서 8000 포트를 허용하면 같은 사내망에서 `http://내PC주소:8000`으로 접속합니다. 이때는 관리자 계정을 만들어 로그인을 켜세요.
- 포트를 바꾸려면 `set PORT=8080` 후 실행(macOS: `PORT=8080 ./start_mac_linux.sh`).

### 버전 관리·자동 업데이트 (로컬 설치판)
설치 폴더가 `git clone`으로 만든 저장소이면, GitHub에 새 버전이 올라올 때 PC에서 바로 받아 올 수 있습니다.

- **시작할 때 자동 확인**: `start_windows.bat`(macOS·Linux `start_mac_linux.sh`)이 실행 전에 새 버전을 확인하고, 바뀐 내용을 보여 준 뒤 업데이트합니다(20초 동안 답이 없으면 자동 진행, 끄기: `set UPDATE_CHECK=0`).
- **화면에서 업데이트**: 관리자에게는 상단에 `⬆ 업데이트 N건`이 표시되고, 관리 → 버전·업데이트에서 바뀐 내용 확인 후 '지금 업데이트'를 누르면 자동으로 다시 시작합니다.
- **안전장치**: 업데이트 전에 `data/app.db`를 `data/backups/`에 백업(최근 10개 보관), `git pull --ff-only`로만 받음(설치 폴더 파일을 직접 고쳤으면 멈춤), requirements.txt가 바뀌면 패키지도 설치.
- **되돌리기**: 관리 화면의 '이 업데이트 되돌리기' 또는 `.venv\Scripts\python -m app.updater rollback`. 데이터는 그대로입니다.
- **명령줄**: `python -m app.updater version | check | apply | rollback`
- 버전 번호는 저장소의 `VERSION` 파일, 바뀐 내용은 커밋 제목으로 표시합니다. 업데이트 기록은 `data/update_log.json`.
- ZIP으로 받은 설치본은 자동 업데이트가 되지 않습니다. `git clone -b <브랜치> <저장소 주소>`로 다시 설치하고 `data` 폴더만 옮기세요.

### 로컬 개발
```bash
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
```
브라우저에서 http://localhost:8000 을 열고 `samples/sample_project.xer`를 업로드해 보세요.

### 팀 서버 배포 (Docker)
```bash
APP_TOKEN=팀비밀번호 docker compose up -d --build
```
- 데이터는 `./data/app.db`(SQLite)에 저장됩니다. 이 파일만 백업하면 됩니다.
- `APP_TOKEN`을 지정하면 처음 접속할 때 토큰을 묻습니다. 사내망 밖에 노출한다면 HTTPS 리버스 프록시(nginx 등)를 함께 쓰세요.

### 테스트
```bash
python -m pytest -q
```
화면 회귀 + 접근성 테스트(Node 20, Playwright 크로미움 필요):
```bash
cd tests/e2e && npm install && npx playwright install chromium && node run.js
```
임시 DB로 서버를 띄워 실제 브라우저로 주요 흐름을 확인하고, 화면마다 axe-core로 접근성(심각·치명 위반은 실패)을 점검합니다. 스크린샷과 참고 항목은 `tests/e2e/out/`에 남습니다. GitHub Actions(`.github/workflows/ci.yml`)에서 pytest와 함께 자동 실행됩니다.
