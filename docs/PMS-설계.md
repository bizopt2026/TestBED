# PMS 2버전(클라이언트·서버) 개발 설계

- 문서 버전: 0.1 (설계 초안) · 대상 코드: 공정관리 분석기 1.9.0 (`claude/exciting-maxwell-95n1if` / `main`)
- 명칭: 지금 개발 중인 프로그램을 **PMS**(Project Management System)로 부르고, 같은 코드에서 두 가지 판을 만든다.
  - **PMS 클라이언트** — 개별 프로젝트 공정관리(현장·공무 담당자 PC)
  - **PMS 서버** — 전사 대시보드 + 프로젝트 공유 저장소(본사)

---

## 1. 요구사항 정리

| 구분 | 요구 | 설계 반영 |
|---|---|---|
| 클라이언트 | n명이 접속, n개 프로젝트 관리 가능하나 **자기 프로젝트 공정관리가 목적** | 지금 앱 그대로(CPM·분석·현장·보고). '내 프로젝트'가 기본 화면 |
| 클라이언트 | 내 프로젝트를 **코드 / 복사·붙여넣기 / 파일**로 넘기면 남의 클라이언트에서 조회 | ① 공유 코드 ② 붙여넣기 텍스트 ③ `.pms` 파일 — 세 가지 모두 같은 '프로젝트 패키지'를 담는 그릇 |
| 클라이언트 | 서버에 있는 타인 프로젝트를 **열람·등록(구독)**하면 내 프로그램에서 조회 | 서버 카탈로그 → '구독' → 내 클라이언트에 **읽기 전용 참조 프로젝트**로 표시, 새 판이 올라오면 자동 갱신 |
| 서버 | 클라이언트의 프로젝트 현황 조회, **대시보드가 메인** | 포트폴리오 대시보드(지금 홈·포트폴리오·마일스톤 공정표 확장) |
| 서버 | **공정 지연 등 문제·이슈 인지**가 핵심 | 이슈 탐지 규칙 엔진(지금 상황판·할 일 함 규칙을 서버로 이동·확장) + 알림 |
| 서버 | 클라이언트 간 정보 공유를 위한 **클라우드 역할** | 프로젝트 패키지 저장소(게시·판 관리·구독·공유 코드) + 동기화 API |

## 2. 벤치마크 (비슷한 방식의 프로그램)

| 제품 | 구조 | 공유·동기화 방식 | PMS에 가져올 점 | 가져오지 않을 점 |
|---|---|---|---|---|
| **Oracle Primavera P6** (Professional + EPPM) | 데스크톱 클라이언트 + 중앙 DB / 웹 | **체크아웃·체크인**: 체크아웃한 프로젝트는 중앙에서 남이 열람만 가능, 체크인해야 반영. 로컬 DB(SQLite)·XML 파일로 체크아웃 | '한 프로젝트 = 한 명의 편집 소유권' 원칙, 파일로도 주고받기 | 체크인 때 캘린더 덮어쓰기 같은 복잡한 병합 |
| **Asta Powerproject** + Enterprise / Asta Vision | 데스크톱 + 엔터프라이즈 서버 + 웹(Vision) | 웹 저장소에서 서버로 체크아웃해 여러 명이 편집, 관리자가 사용자 잠금 | 웹 '보기 전용'과 데스크톱 '편집'의 역할 분리 | 서버가 항상 켜져 있어야 하는 다중 사용자 편집 |
| **Microsoft Project** (데스크톱 + Project Server / Project Online) | 데스크톱 + 서버(PWA) | 체크아웃 → **게시(Publish)** 해야 다른 사람·보고서에 보임 | **'게시' 개념**: 작업 중인 내용과 공개된 판을 분리 | Project Online은 **2026-09-30 종료**(사내 공정관리 대체 수요 근거) |
| **Oracle Primavera Cloud / Aconex**, **Procore** | 클라우드 전용(SaaS) | 실시간 공유 DB | 웹 대시보드·이슈 알림, 현장 앱 | 외부 클라우드 저장(보안 보류 항목: 외부 연동) |
| **Git / 문서 협업 도구** | 분산 저장소 | 커밋(판)·푸시·풀, 변경 이력 | **판(버전) 불변 저장, 해시로 무결성 확인**, 오프라인 작업 후 동기화 | 사용자에게 병합 충돌을 직접 풀게 하기 |

**결론 — PMS 방식:** P6·MS Project의 **'편집은 소유자 클라이언트, 공개는 게시한 판'** 원칙에, Git의 **'판 불변 + 해시'**를 더한다. 실시간 공동 편집(동시 편집 병합)은 하지 않는다. 공정표 원본은 소유자가 바꾸고, 다른 사람은 게시된 판을 보고, 코멘트·리스크 같은 협업 기록만 서버를 통해 함께 쓴다.

## 3. 전체 구조

```
  [PMS 클라이언트 A]                 [PMS 서버 (본사)]                 [PMS 클라이언트 B]
  내 프로젝트 편집 ──게시(push)──▶  프로젝트 저장소 (판 v1, v2 …) ──구독(pull)──▶  A의 프로젝트 조회(읽기 전용)
  .pms 파일 / 붙여넣기 / 공유 코드 ─────────────────────────────────────────────▶  가져오기
                                    대시보드 · 이슈 탐지 · 알림
                                    협업 기록(코멘트·리스크·담당자) 동기화
```

- **같은 코드, 두 판**: 환경 변수 `PMS_EDITION=client|server`로 켜는 기능을 나눈다. 계산 엔진·화면 부품·디자인은 공유한다.
- **클라이언트는 서버 없이도 완전 동작**(오프라인 우선). 서버가 있으면 게시·구독·대시보드가 켜진다.
- **서버는 공정을 다시 계산할 수 있다**(같은 엔진). 그래서 게시된 판만으로 대시보드 지표를 직접 만든다.

### 3.1 지금 코드에서 어디로 가는가

| 지금 모듈 | 클라이언트 | 서버 | 비고 |
|---|---|---|---|
| `schedule.py`, `analysis.py`, `metrics.py`, `forensic.py`, `risk.py`, `recovery.py`, `evm.py` (CPM·분석) | ● | ● | 서버는 게시된 판을 계산해 대시보드 지표 생성 |
| `importers.py`, `xer_parser.py`, `mpp_convert.py` | ● | ○ | 서버는 패키지 안 XER만 읽음 |
| 화면: 공정표·What-if·룩어헤드·현장 모드·월간 점검·보고서 센터 | ● | ○(조회) | 서버에서는 읽기 전용 화면으로 재사용 |
| 화면: 홈 포트폴리오·마일스톤 공정표·할 일 함 | ○(내 것) | ● | 서버 대시보드의 출발점 |
| `workflow.py`(상황판·이슈 규칙), `notify.py`(알림) | ● | ● | 이슈 규칙은 서버가 전사 기준으로 실행 |

| `updater.py`(자동 업데이트) | ● | ● | 판별로 다른 시작 스크립트 |
| 새로: `package.py`, `hub.py`, `sync.py`, `issues.py` | ● | ● | 아래 4~6장 |

## 4. 프로젝트 패키지 (`.pms`) — 세 가지 공유 방식의 공통 그릇

모든 공유(파일·붙여넣기·공유 코드·서버 게시)는 **같은 패키지 형식**을 쓴다. 그래서 받는 쪽은 그릇 종류와 상관없이 한 가지 가져오기 기능만 있으면 된다.

```
project.pms  (zip)
├─ manifest.json      형식 버전, 프로젝트 ID·이름, 판 번호, 게시자, 게시 시각, Data Date, 원본 형식, 파일별 SHA-256
├─ schedule.xer       원본 공정표 (XER, MS Project는 변환된 XER 또는 MSPDI)
├─ settings.json      계산 옵션, 품질 기준, 상태 기준
├─ records.json       리스크·제약·약속·코멘트·월간 점검 기록·베이스라인 지정
├─ summary.json       미리 계산한 요약(준공·여유·건전성·SPI·마일스톤) — 받는 쪽이 계산 전에 바로 표시
└─ attachments/       (선택) 현장 사진 등. 기본은 제외
```

| 공유 방식 | 쓰는 상황 | 구현 |
|---|---|---|
| **파일** (`.pms`) | 메일·메신저·USB로 전달, 서버 없는 현장 | '내보내기' → `.pms` 저장, '가져오기' → 끌어다 놓기 |
| **복사·붙여넣기** | 메신저로 바로 보낼 때(작은 프로젝트) | 패키지를 압축 → Base64 텍스트(`PMS1:` 머리 + 체크섬). 약 1MB 이하만 허용하고, 넘으면 파일·코드로 안내 |
| **공유 코드** (예: `PMS-7K3Q-9XR2`) | 서버가 있을 때 가장 간단 | 게시된 판을 가리키는 짧은 코드. **만료 기간·사용 횟수·대상(누구나/조직/지정 사용자)** 설정, 언제든 취소 |
| **서버 게시·구독** | 상시 공유 | 게시하면 서버 카탈로그에 등록, 다른 사람은 '구독' → 새 판이 올라오면 자동 갱신 |

- **무결성**: manifest의 SHA-256으로 손상·변조를 확인한다.
- **보안**: 붙여넣기·파일은 선택적으로 **암호**(AES-GCM, 암호에서 키 유도)로 잠글 수 있다. 공유 코드는 서버 권한 검사를 거친다.
- **받은 프로젝트는 '참조 프로젝트'**: 읽기 전용, 출처(누가·언제 게시한 몇 번째 판)를 항상 표시한다. 편집하려면 '내 프로젝트로 복제'(새 프로젝트 ID)한다. 원본과 섞이지 않는다.

## 5. 클라이언트 설계

| 기능 | 내용 | 지금 기능과의 관계 |
|---|---|---|
| 내 프로젝트 | 내가 소유·편집하는 프로젝트. 홈 기본 화면 | 지금 프로젝트 권한(소유자·멤버) 그대로 |
| 참조 프로젝트 | 파일·붙여넣기·코드·구독으로 받은 남의 프로젝트(읽기 전용, 판 표시) | 새로 |
| 게시 | '서버에 게시' → 판 번호 증가, 변경 요약 자동 작성 | 월간 점검 마지막 단계·확정본과 연결(점검 완료 → 게시 권장) |
| 편집 소유권(잠금) | 한 프로젝트의 공정표 편집은 소유 클라이언트 한 곳. 다른 PC에서 편집하려면 서버에서 **소유권 가져오기**(P6 체크아웃과 같은 개념) | 지금 '쓰기 권한' 확장 |
| 오프라인 | 서버 없이 모든 기능 동작, 게시·코멘트는 대기열에 쌓았다가 연결되면 전송 | 현장 모드 오프라인 대기열 일반화 |
| 동기화 상태 | 상단에 '서버 연결됨 · 마지막 게시 v12 · 보내지 않은 기록 3건' | 새로 |

**한 사람이 여러 PC**를 쓰는 경우: 서버 계정으로 로그인하면 '내 프로젝트' 목록이 서버에서 내려오고, 한 번에 한 PC만 편집 소유권을 가진다.

## 6. 서버 설계

### 6.1 대시보드 (메인 화면)

| 영역 | 내용 |
|---|---|
| 이슈 보드 | 심각도(위험·주의)별 이슈 목록, 프로젝트·현장·담당 PM 필터, 새로 생긴 이슈 강조, 확인·조치 중·해결 상태 |
| 포트폴리오 | 프로젝트 카드(상태 배지·준공·목표 대비·건전성·SPI), 지도/목록 전환, 사업부·발주처·공종별 묶기 |
| 추세 | 전사 지연 일수 합, 위험 프로젝트 수, 게시 준수율(이번 달 게시 완료 비율), 월별 변화 |
| 마일스톤 공정표 | 지금 포트폴리오 마일스톤을 확장(주요 마일스톤·계획 대비, 이번 달 도래) |
| 게시 현황 | 프로젝트별 마지막 게시일, **게시 지연(이번 달 미게시)** 경고 |

### 6.2 이슈 탐지 규칙 (서버가 게시마다 실행)

| 규칙 | 조건(기본값, 조직·프로젝트별로 조정) | 심각도 |
|---|---|---|
| 준공 지연 | 목표 준공 대비 여유 < 0일 | 위험 |
| 직전 대비 악화 | 예상 준공이 직전 판보다 7일 이상 늦어짐 | 위험 / 3일 이상 주의 |
| 음수 여유 | 미완료 작업 중 TF < 0 | 위험 |
| 마일스톤 지연 | 주요 마일스톤 계획 대비 +N일, 또는 30일 안 도래 마일스톤이 위험 | 주의~위험 |
| 성과 지수 | SPI < 0.9 (주의), < 0.8 (위험) | |
| 공정표 품질 | 건전성 점수 급락(−10점), 선후행 누락 급증, 공기 압축 의심 | 주의 |
| 운영 | 이번 달 미게시, 월간 점검 미완료, 기한 지난 제약·리스크 대응 없음 | 주의 |

- 이슈는 **상태(새로 · 확인 · 조치 중 · 해결)**와 담당자를 가진다. 같은 원인이 다음 판에도 계속되면 새 이슈를 만들지 않고 '지속 N개월'로 누적한다.
- 알림: 서버 알림함 + 클라이언트 알림(+ 바탕화면 알림). **메일 발송은 보안 보류 항목이라 제외**한다.

### 6.3 저장소(클라우드 역할)

| 데이터 | 설명 |
|---|---|
| projects | 프로젝트 ID(전사 고유), 이름, 소유자, 사업부, 현재 편집 소유 클라이언트 |
| snapshots | 게시된 판(불변): 판 번호, 패키지 파일, 해시, 게시자, 변경 요약, 계산 결과 캐시 |
| subscriptions | 누가 어느 프로젝트를 구독하는지(참조 프로젝트) |
| share_codes | 공유 코드, 대상·만료·사용 횟수·취소 여부 |
| issues | 이슈와 상태 이력 |
| collab | 코멘트·리스크·담당자 지정 등 협업 기록(서버가 기준) |
| devices | 클라이언트 기기 등록(기기 토큰), 마지막 접속 |
| audit | 게시·다운로드·코드 사용·권한 변경 기록 |

## 7. 동기화 규칙

| 데이터 | 기준(누가 진본) | 충돌 처리 |
|---|---|---|
| 공정표(XER)·계산 옵션 | **편집 소유권을 가진 클라이언트** | 소유권이 한 곳이므로 충돌 없음. 서버의 판은 불변 |
| 코멘트 | 서버 | 추가만 하므로 충돌 없음(오프라인 작성분은 연결 시 순서대로 등록) |
| 리스크·제약·담당자 | 서버 | 지금의 `base_updated_at` 충돌 확인(409) → '덮어쓰기 / 다시 불러오기' 재사용 |
| 월간 점검 기록·확정본 | 서버 | 판에 묶여 불변 |
| 개인 설정 | 서버 계정(없으면 로컬) | 마지막 저장 우선 |

**동기화 API(초안)** — 기기 토큰 + HTTPS

```
POST /hub/v1/projects/{pid}/snapshots        게시 (패키지 업로드, 해시 검사)
GET  /hub/v1/catalog?q=&org=                  열람 가능한 프로젝트 목록
POST /hub/v1/projects/{pid}/subscribe         구독(내 클라이언트에 참조 프로젝트로 등록)
GET  /hub/v1/projects/{pid}/snapshots/latest  최신 판 받기 (ETag로 변경 없으면 304)
POST /hub/v1/share-codes                      공유 코드 만들기 {pid, 판, 대상, 만료}
GET  /hub/v1/share-codes/{code}               코드로 패키지 받기
POST /hub/v1/projects/{pid}/lock              편집 소유권 가져오기 / 반납
GET  /hub/v1/events?since=                    변경 알림(구독 프로젝트 새 판, 이슈, 코멘트) — 처음엔 주기적 확인, 이후 SSE
```

## 8. 보안

- 클라이언트 ↔ 서버: HTTPS, 사용자 로그인 + **기기 토큰**(서버에서 기기별로 끊을 수 있음).
- 권한: 지금의 '읽기는 모두, 쓰기는 자기 프로젝트' 규칙을 서버에서 조직 단위로 확장(사업부·프로젝트별 공개 범위: 전사 / 사업부 / 지정 사용자).
- 공유 코드: 추측이 어려운 무작위 코드, 만료·사용 횟수 제한, 감사 기록, 즉시 취소.
- 파일·붙여넣기: 선택 암호화, 해시 검사.
- **보류 유지**: SSO, 메일 자동 발송, 외부 시스템 연동은 이번 설계에서도 제외(별도 승인 후).

## 9. 배포·버전 관리

| 항목 | 클라이언트 | 서버 |
|---|---|---|
| 설치 | 지금 `install_windows.bat` (PC) | Docker(사내 서버 또는 사내망 VM). `docker-compose.yml`에 서버 판 설정 |
| 실행 | `start_windows.bat` (`PMS_EDITION=client`) | `PMS_EDITION=server` |
| 업데이트 | 지금 자동 업데이트(GitHub `main` pull) | 같은 방식 또는 이미지 재배포 |
| 호환 | **패키지 형식 버전**과 **API 버전**(`/hub/v1`)을 분리. 서버는 한 단계 이전 클라이언트까지 지원 | |

## 10. 개발 단계 (제안)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **P0 정리** | 명칭 PMS로 변경, `PMS_EDITION` 판 구분, 클라이언트/서버 화면 메뉴 분기 | 같은 코드로 두 판이 뜨고 기존 테스트 통과 |
| **P1 패키지** | `.pms` 내보내기·가져오기, 붙여넣기 텍스트, 참조 프로젝트(읽기 전용·출처 표시·복제) | 서버 없이 두 클라이언트 간 파일·붙여넣기로 공유 |
| **P2 서버 저장소** | 게시·판 관리·카탈로그·구독·공유 코드·기기 토큰 | 클라이언트 A 게시 → B가 코드/구독으로 조회, 새 판 자동 갱신 |
| **P3 서버 대시보드** | 이슈 탐지 엔진, 이슈 보드, 포트폴리오, 게시 현황, 알림 | 지연 시나리오에서 이슈가 생기고 해결까지 상태 관리 |
| **P4 협업 동기화** | 코멘트·리스크·담당자 서버 기준 동기화, 오프라인 대기열, 편집 소유권 | 두 PC에서 협업 기록 충돌 없이 반영, 소유권 이전 |
| **P5 운영** | 서버 백업·복구, 감사 화면, 성능(프로젝트 100개·판 1,000개), 설치 안내 | 운영 점검표 통과 |

각 단계마다 지금처럼 서버 테스트(pytest) + 화면 테스트(E2E·접근성·기준 이미지)를 추가한다. P2부터는 **클라이언트 2대 + 서버 1대를 띄우는 E2E 시나리오**를 둔다.

## 11. 정해야 할 것 (결정 필요)

1. **서버 위치**: 사내 서버(사내망 전용) / 사내 클라우드 VM / 외부 클라우드 — 외부 클라우드는 보안 보류 항목과 관련.
2. **계정 기준**: 서버 계정 하나로 통일할지, 클라이언트 단독 계정도 허용할지.
3. **공개 범위 기본값**: 게시하면 전사 공개 / 사업부 공개 / 지정 사용자.
4. **사진 등 첨부 파일**을 패키지·서버에 포함할지(용량).
5. **이슈 기준값**(7장 표)을 조직 공통으로 정할 담당 부서.
6. **명칭**: 'PMS 클라이언트 / PMS 서버' 그대로 쓸지, 화면 표시 이름(예: PMS 현장판 / PMS 본사판).
