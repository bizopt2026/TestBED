# PMS 배포·운영 가이드

버전 3.0.0 · 대상: 사내 서버 담당자(PMS 대시보드), 현장 PC 설치 담당자, PMS 관리자

사용 방법은 [사용자 매뉴얼](사용자-매뉴얼.md)을 보세요.

---

## 1. 구성

```
 현장 PC (PMS 현장, 각자)  ──게시·구독·AI 요청──▶  사내 서버 (PMS 대시보드, 1대)
   http://localhost:8000                             http://pms-server:8100
   data/app.db (내 프로젝트)                         data/app.db (전사 게시본·이슈·계정)
                                                      Claude CLI (AI 실행)
```

- 프로그램은 하나이고 `PMS_EDITION` 으로 판을 정합니다: `client`(PMS 현장, 기본) / `server`(PMS 대시보드).
- 데이터는 SQLite 파일 하나(`data/app.db`)입니다. 따로 DB 서버가 필요 없습니다.
- 버전이 다른 현장과 대시보드도 함께 쓸 수 있지만, **업데이트는 대시보드를 먼저** 하세요(새 기능은 대시보드가 있어야 동작하고, 없으면 조용히 건너뜁니다).

### 요구 사항

| 항목 | 내용 |
|---|---|
| Python | 3.10 이상 (3.11 이상 권장) |
| git | 자동 업데이트에 필요 (ZIP 설치는 수동 업데이트) |
| Java 17 이상 | 선택: `.mpp` 읽기. 없으면 MS Project XML로 저장해 올리면 됨 |
| Claude CLI | 선택: AI 기능. 대시보드 서버에 설치·로그인 (API 키 사용 안 함) |
| 네트워크 | 현장 PC → 대시보드 포트(기본 8100). 설치·업데이트 때 GitHub·PyPI |
| GitHub 접근 | 저장소가 비공개면 각 PC의 git 이 읽기 권한으로 로그인되어 있어야 자동 업데이트가 됩니다(읽기 전용 토큰 또는 배포 키 권장) |
| 디스크 | 프로그램 약 300MB(가상 환경 포함) + 데이터(프로젝트 수백 개 기준 수백 MB) |

## 2. 사내 서버: PMS 대시보드 설치

### 2.1 Windows 서버
```bat
git clone https://github.com/bizopt2026/TestBED.git C:\PMS
cd C:\PMS
install_windows.bat
```
- 설치 끝에 **관리자 계정을 만드세요**(대시보드는 계정 필수). 나중에 만들려면: `.venv\Scripts\python -m app.auth create-admin <아이디>`
- 실행: `start_dashboard_windows.bat` (포트 8100, 모든 주소에서 접속 허용)
- **방화벽**에서 TCP 8100 인바운드 허용(사내망만).
- 서버 재부팅 후 자동 실행이 필요하면 작업 스케줄러에 `start_dashboard_windows.bat` 를 "로그온 여부와 관계없이" 등록하세요.

### 2.2 Linux 서버
```bash
git clone https://github.com/bizopt2026/TestBED.git /opt/pms && cd /opt/pms
./install_mac_linux.sh            # 관리자 계정 만들기: y
PMS_EDITION=server HOST=0.0.0.0 PORT=8100 ./start_mac_linux.sh
```
상시 운영은 systemd 서비스로 등록합니다(종료 코드 3은 "업데이트 후 다시 시작"이므로 재시작 대상).
```ini
# /etc/systemd/system/pms-dashboard.service
[Unit]
Description=PMS 대시보드
After=network.target
[Service]
WorkingDirectory=/opt/pms
Environment=PMS_EDITION=server
Environment=SECURE_COOKIE=0
ExecStart=/opt/pms/.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8100
Restart=always
User=pms
[Install]
WantedBy=multi-user.target
```

### 2.3 Docker (선택)
```bash
ADMIN_USERNAME=admin ADMIN_PASSWORD='...' docker compose up -d --build
```
- 기본은 PMS 대시보드(`PMS_EDITION=server`), 포트 8000, 데이터는 `./data`.
- 컨테이너 안에서는 AI가 기본으로 꺼져 있습니다(Claude CLI 로그인 정보가 필요). AI를 쓰려면 2.1·2.2의 직접 설치를 권장합니다.
- 3.0.0 릴리스에서 Docker 이미지는 빌드 검증을 하지 못했습니다(검증 환경에 Docker 데몬 없음). 운영 전 한 번 빌드·기동을 확인하세요.

### 2.4 AI(Claude CLI)
1. 대시보드 서버에 Claude CLI를 설치하고 서버 계정으로 로그인합니다.
2. PMS를 다시 시작하면 관리 → AI 상태가 "사용 가능"으로 바뀝니다.
3. 프로젝트별 AI 금지는 관리 → AI 정책에서 정합니다.
- 관련 설정: `AI_PROVIDER`(off로 끔), `AI_MODEL`, `AI_TIMEOUT`(초, 기본 300), `AI_MAX_CONCURRENCY`(기본 2), `CLAUDE_BIN`(CLI 경로).

### 2.5 HTTPS
사내망 HTTP로도 동작합니다. HTTPS로 운영하려면 IIS·nginx 등 역방향 프록시 뒤에 두고 `SECURE_COOKIE=1` 을 설정하세요.

## 3. 현장 PC: PMS 현장 설치

```bat
git clone https://github.com/bizopt2026/TestBED.git C:\PMS
cd C:\PMS
install_windows.bat          :: 혼자 쓰는 PC면 관리자 계정 N
start_windows.bat            :: http://localhost:8000 이 열림
```
- macOS: `./install_mac_linux.sh` → `./start_mac_linux.sh`
- 대시보드 연결: 프로그램의 **내 설정 → PMS 대시보드 연결**(주소 예: `http://pms-server:8100`). 여러 PC에 미리 넣으려면 환경 변수 `PMS_HUB_URL` 을 설정하세요.
- 사내 프록시를 거쳐야 대시보드에 닿는 환경이면 `PMS_HUB_USE_PROXY=1`.

## 4. 업데이트

### 4.1 자동 업데이트(기본)
시작 스크립트가 실행될 때마다 GitHub의 `main` 브랜치에 새 버전이 있는지 확인하고, 있으면 20초 안에 묻고 적용합니다.

적용 순서는 다음과 같습니다.
1. DB를 `data/backups/` 에 백업합니다(최근 10개 보관).
2. `git pull --ff-only` 로 새 버전을 받습니다.
3. `requirements.txt` 가 바뀌었으면 패키지를 설치합니다.
4. 프로그램을 다시 시작합니다.

- 확인을 끄려면 `UPDATE_CHECK=0`.
- 관리 화면 **버전·업데이트**에서도 확인·적용·되돌리기를 합니다.
- 명령줄: `python -m app.updater check | apply | rollback | version`

> **주의**: `main` 에 올라간 코드는 다음 실행 때 모든 설치 PC에 배포됩니다. `main` 병합은 릴리스로 취급하세요.

### 4.2 되돌리기
관리 → 버전·업데이트 → 되돌리기, 또는 `python -m app.updater rollback` (코드만 직전 버전으로, 데이터는 그대로). 데이터까지 되돌리려면 5.2의 복구를 함께 하세요.

### 4.3 3.0.0 업데이트 확인 결과
| 확인 항목 | 결과 |
|---|---|
| 1.6.0 / 2.0.0 / 2.5.0 에서 만든 DB를 3.0.0으로 열기 | 계정·업로드·리스크·제약·약속·코멘트·설정 유지, 주요 화면·백업 정상 |
| 2.5.0 설치본의 자동 업데이트(check → apply) | 최신판으로 적용, DB 백업 생성 |
| 되돌리기 → 다시 적용 | 정상 |
| 새 PC 설치(install → start) | 정상, 최신 패키지로 단위 테스트 79개 통과 |

업데이트 뒤 바뀌는 점:
- **상태 표시**: 이슈 규칙도 상태에 반영되므로, 일부 프로젝트가 "정상"에서 "주의·위험"으로 바뀌어 보일 수 있습니다.
- **비밀번호 규칙 강화**: 기존 비밀번호는 그대로 쓰고, 새로 정할 때만 적용됩니다.
- **현장 PC 연결**: 현장 PC는 대시보드에 한 번 다시 연결하면 편집 소유권 유지 기능이 적용됩니다.

## 5. 백업과 복구

### 5.1 백업
- **수동**: 관리 → 운영 → **지금 백업 내려받기**(온라인 백업, 사용 중에도 가능)
- **자동**: 업데이트할 때마다 `data/backups/` 에 저장(최근 10개)
- **권장**: 대시보드 서버는 매일 `data/` 폴더를 다른 디스크·NAS로 복사(작업 스케줄러·cron). 프로그램이 실행 중이어도 관리 화면 백업 파일은 일관됩니다.

### 5.2 복구
1. PMS를 멈춥니다.
2. `data/app.db` 를 다른 이름으로 보관합니다.
3. 백업 파일을 `data/app.db` 로 복사합니다.
4. PMS를 다시 시작합니다.

### 5.3 상태 확인(감시)
- `GET /api/health`(로그인 필요): 판, 버전, 프로젝트 수, DB 크기, 마지막 게시, 열린 이슈, 연결 기기
- 관리 → 운영 패널에서도 같은 정보를 봅니다.

## 6. 설정 값(환경 변수)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PMS_EDITION` | client | `server` 면 PMS 대시보드 |
| `PMS_AI_MODE` | server | `server`(연결된 현장의 AI는 대시보드에서) · `local` · `auto` · `off` |
| `PMS_HUB_URL` | (없음) | 현장 PC가 쓸 대시보드 주소(내 설정에서도 지정 가능) |
| `PMS_HUB_TIMEOUT` | 30 | 대시보드 요청 제한 시간(초) |
| `PMS_HUB_USE_PROXY` | 0 | 1이면 시스템 프록시 사용 |
| `HOST` / `PORT` | 127.0.0.1 / 8000 (대시보드 스크립트는 0.0.0.0 / 8100) | 접속 주소·포트 |
| `DB_PATH` | data/app.db | 데이터 파일 위치 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | (없음) | 첫 실행 때 관리자 생성(비밀번호 10자 이상, 2가지 이상 문자 종류) |
| `SESSION_HOURS` | 12 | 로그인 유지 시간 |
| `SECURE_COOKIE` | 0 | HTTPS 운영 시 1 |
| `APP_TOKEN` | (없음) | 계정 없이 쓸 때 팀 접근 토큰 |
| `MAX_UPLOAD_MB` | 100 | 업로드 최대 크기 |
| `AI_PROVIDER` | (자동) | `off` 면 AI 끔 |
| `AI_MODEL` / `AI_MODEL_BULK` | (CLI 기본) | AI 모델 |
| `AI_TIMEOUT` / `AI_MAX_CONCURRENCY` / `AI_MAX_BUDGET_USD` | 300 / 2 / (없음) | AI 실행 제한 |
| `CLAUDE_BIN` | (자동) | Claude CLI 경로 |
| `JAVA_HOME` / `MPP_TIMEOUT` | (자동) / 120 | .mpp 읽기 |
| `UPDATE_CHECK` | 1 | 0이면 시작할 때 업데이트 확인 안 함 |

## 7. 보안 점검표

- [ ] 대시보드에 관리자 계정을 만들었고, 기본 계정·약한 비밀번호가 없다
- [ ] 대시보드 포트(8100)는 사내망에서만 열려 있다
- [ ] HTTPS 운영 시 `SECURE_COOKIE=1`
- [ ] `data/` 폴더를 매일 다른 곳에 백업한다
- [ ] 퇴사·이동자 계정은 관리 → 사용자에서 사용 중지, 관리 → 연결된 PMS 현장에서 기기 끊기
- [ ] AI를 쓰면 안 되는 프로젝트를 관리 → AI 정책에서 금지로 지정했다

보류 중인 기능(별도 승인 전까지 만들지 않음): 외부 RFI·제출물 연동, 정기 메일 발송, SSO.

## 8. 알려진 한계 (3.0.0)

- **현장 모드 오프라인**: 앱을 열어 둔 상태에서만 됩니다. 오프라인에서 새로 고침하면 열리지 않습니다.
- **리스크·제약 동기화**: "나중에 고친 쪽 우선"은 PC 시계를 기준으로 합니다. 사내 PC와 서버의 시간이 맞아야 합니다.
- **약속(PPC)**: 게시한 현장 기준으로만 맞춥니다(양방향 아님).
- **.pms 파일**: 암호 잠금이 없습니다. 민감한 프로젝트는 대시보드 공유 코드(대상 지정·기간 제한)를 쓰세요.
- **규모**: 프로젝트 100개 규모의 성능 측정은 아직 하지 않았습니다.

## 9. 문제 해결

| 증상 | 확인 |
|---|---|
| 현장에서 대시보드 연결 실패 | 주소·포트·방화벽, `curl http://pms-server:8100/api/config` 가 `"edition":"server"` 인지 |
| "PMS 대시보드 연결이 끊겼습니다" | 관리자가 기기를 끊었거나 계정이 중지됨 → 내 설정에서 다시 연결 |
| AI가 "사용할 수 없음" | 대시보드 서버의 Claude CLI 설치·로그인, `AI_PROVIDER` 가 off 인지, 프로젝트 AI 금지 여부 |
| .mpp 업로드 실패 | Java 17 이상 설치 여부, 또는 MS Project에서 XML로 저장해 올리기 |
| 업데이트 확인 "불가" | ZIP으로 설치했거나 git이 없음 → git clone 으로 다시 설치(데이터 폴더 복사) |
| 시작 시 `ADMIN_PASSWORD 를 쓸 수 없습니다` | 비밀번호 규칙(10자 이상, 2가지 이상 문자 종류)에 맞게 바꾸기 |
| 로그인 잠김 | 5회 실패 시 그 PC에서 10분 잠금. 기다리거나 다른 PC에서 로그인 |
